**Session:** `plan-2026-01-24-1200`
**Created:** 2026-01-24
**Status:** Ready for execution

---

## 1. Problem Statement

The pharmacy search feature returns only ~4 pharmacies instead of the expected 25. This occurs because:
1. Google Places API returns 20 results per page, but only ~20% have phone numbers
2. Our code filters out pharmacies without phone numbers (required for calling)
3. We only fetch 1 page initially, resulting in ~4 usable pharmacies

Users need more pharmacy options to increase the chance of finding medication availability.

---

## 2. Scope & Boundaries

**IN SCOPE:**
- Modify `pharmacySearchService.searchNearby()` to auto-paginate
- Add configuration for target pharmacy count (default: 25)
- Add maximum page limit to cap API costs (default: 5 pages)
- Update route defaults in `searches.ts`

**OUT OF SCOPE:**
- UI changes (no frontend modifications)
- Call system changes (no orchestrator modifications)
- Database schema changes

## Research Summary

**Root Cause:** Google Places API doesn't have phone numbers for ~80% of pharmacy listings. With only 1 page fetched (20 results), we get ~4 pharmacies with phones.

**Solution:** Fetch multiple pages (up to 5) until 25 valid pharmacies are collected or all pages exhausted.
