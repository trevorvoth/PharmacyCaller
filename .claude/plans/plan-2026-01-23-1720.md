# Plan: Interactive Map View for Pharmacy Search

**Session ID:** plan-2026-01-23-1720
**Created:** 2026-01-23
**Approach:** Full Google Maps Integration with @vis.gl/react-google-maps

---

## 1. Problem Statement

**Problem:** During medication searches, users see a text-based list of pharmacies but have no geographic context. They cannot visualize where pharmacies are located relative to their position or understand the spatial distribution of their search results.

**Solution:** Add an interactive Google Maps view to the search results page showing:
- User's current location
- All pharmacies as colored markers that update in real-time as calls progress
- Clickable markers with pharmacy details (name, address, call status)
- Collapsible side panel preserving the existing list view

---

## 2. Scope & Boundaries

### IN SCOPE
- Google Maps integration using `@vis.gl/react-google-maps`
- AdvancedMarker pins with status-based colors
- User location marker (blue dot)
- InfoWindow popups on marker click showing pharmacy details
- Real-time marker color updates via existing WebSocket events
- Collapsible side panel for list view (desktop: 35% width, mobile: bottom sheet)
- Backend API change to expose pharmacy lat/lng coordinates
- Environment variables for Google Maps API key and Map ID

### OUT OF SCOPE
- Selecting/prioritizing pharmacies from the map
- Turn-by-turn directions
- Marker clustering (only 10-20 pharmacies)
- Filtering from the map (existing filter UI handles this)
- Mobile bottom sheet (phase 2 enhancement)
- Accessibility icons on markers (phase 2 enhancement)

---

## 3. Success Criteria

1. **Map displays correctly** - Google Map renders on SearchPage with user location centered
2. **Pharmacy markers visible** - All pharmacies in search results show as colored pins
3. **Real-time updates work** - Marker colors change when call status updates (e.g., pending → calling → ready)
4. **Click interaction works** - Clicking a marker shows InfoWindow with pharmacy name, address, and status
5. **List remains functional** - Existing pharmacy list works in collapsible side panel
6. **Bidirectional highlight** - Clicking a marker highlights the list item; clicking list item zooms to marker
7. **No performance regression** - Page load time increases by < 500ms
8. **Environment configured** - Google Maps API key and Map ID added to `.env`

## 5. Dependencies

### External Dependencies
- `@vis.gl/react-google-maps` - Google Maps React wrapper
- Google Maps JavaScript API enabled in Google Cloud Console
- Google Maps Map ID (created in Cloud Console)

### Environment Variables
- `VITE_GOOGLE_MAPS_API_KEY` - API key for Maps JavaScript API
- `VITE_GOOGLE_MAPS_MAP_ID` - Map ID for AdvancedMarker support

### Internal Dependencies
- Backend must expose lat/lng before frontend can render markers (Task 1 → Tasks 5-8)
- Map component depends on package installation (Task 3 → Task 5)
- SearchPage integration depends on both map component and layout (Tasks 5, 9 → Task 10)

### Existing Systems Used
- WebSocket context (`WebSocketContext.tsx`) - for real-time status updates
- Pharmacy status colors from `PharmacyCard.tsx` - reuse color scheme
- Geolocation from `DashboardPage.tsx` - already captures user location

## 6. Risks & Mitigations

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| Google Maps API key not configured | Map won't render | Medium | Add clear setup instructions in README, graceful fallback to list-only view |
| Map ID not created | AdvancedMarker won't work | Medium | Document Map ID creation steps, test with basic markers as fallback |
| API billing concerns | Unexpected costs | Low | 10k free loads/month should suffice; add usage monitoring |
| Bundle size increase | Slower page load | Low | Map library is ~50KB gzipped; lazy-load map component |
| Geolocation denied | No user location marker | Medium | Show map centered on first pharmacy instead |
| WebSocket disconnect | Markers don't update | Low | Existing reconnect logic handles this; markers still show static state |

## Research Notes

### Codebase Findings
- Backend stores lat/lng in `PharmacyResult` table but doesn't expose it in API
- WebSocket events `call_status_update`, `pharmacist_ready` already exist
- Status colors defined in `PharmacyCard.tsx` statusConfig

### Google Maps API
- Recommended library: `@vis.gl/react-google-maps`
- AdvancedMarker + Pin for custom colored markers
- InfoWindow with `useAdvancedMarkerRef` hook
- 10,000 free map loads/month

### UX Best Practices
- Split view: collapsible side panel (desktop), bottom sheet (mobile)
- Don't rely on color alone - use shapes/icons for accessibility
- Status colors: gray (pending), amber (calling), blue (on hold), green (ready), red (failed)
