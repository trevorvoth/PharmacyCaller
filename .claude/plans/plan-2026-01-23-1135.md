# Plan: Search/Pharmacy Flow - Pagination & Filtering

**Session ID:** plan-2026-01-23-1135
**Created:** 2026-01-23
**Status:** Ready for execution

---

## 1. Problem Statement

The current pharmacy search fetches a fixed set of pharmacies from Google Places API and has no filtering capabilities. Users cannot filter by pharmacy chain or operating hours, and the system is limited to 20 pharmacies per search.

This plan adds:
1. Pagination support to fetch additional pharmacies on-demand (up to 60 total)
2. Chain filtering (CVS, Walgreens, Rite Aid, etc.)
3. Hours filtering (only open pharmacies)

---

## 2. Scope & Boundaries

### In Scope
- Google Places API pagination (next page token support)
- Chain filter parameter on search endpoint
- Hours filter parameter on search endpoint
- Frontend filter UI (checkboxes for chains, toggle for "open now")
- Update `pharmacySearchService` to handle pagination
- Store next page token in Redis for retrieval when reserves run low

### Out of Scope
- Changing the core call orchestration logic
- Pharmacy hours caching/prediction
- User-saved filter preferences
- Distance-based filtering (already supported via radius)

---

## 3. Success Criteria

1. **Pagination works** - When reserves run low, system automatically fetches next page of results
2. **Chain filter works** - User can select specific chains, only those chains appear in results
3. **Hours filter works** - User can toggle "open now", only currently open pharmacies appear
4. **API calls minimized** - Maximum 3 API calls per search (initial + 2 pages)
5. **No regressions** - Existing call flow continues to work correctly
6. **Filter UI functional** - Frontend shows filter controls before search starts

## 6. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Next page token expires (2 hours) | Medium | Low | Store token creation time, refetch if expired |
| Google Places API rate limits | Low | High | Implement exponential backoff, cache results |
| Chain filter doesn't match expected names | Medium | Medium | Map common variations (e.g., "CVS Pharmacy" → "CVS") |
| Opening hours data not available for all pharmacies | High | Medium | Show "hours unknown" instead of filtering out |
| Filter UI adds complexity for users | Low | Low | Default to "no filters" for simple experience |
